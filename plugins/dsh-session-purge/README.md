# dsh-session-purge

Безвозвратное удаление **архивных** сессий DSH — у штатного харнесса удаления
сессий нет, они только архивируются, и список со временем разрастается.

Плагин даёт два входа:

- **HTTP-маршрут `POST /api/session.purge`** — его вызывают корзина у
  архивной строки и кнопка «Удалить архивные (N)» в настройках сайдбара
  `dsh-sidebar-opencode`. Открытая сессия не нужна: запрос идёт через
  `/api`-мост Connection и аутентифицируется cookie страницы.
  - одна сессия: тело `{ "sessionId": "session-<uuid>" }`, ответ — JSON
    `{ ok: true, … }` или ошибка с HTTP-статусом;
  - пакет: тело `{ "sessionIds": ["session-…", …] }` (до 500 id после
    дедупликации). Ответ всегда HTTP 200:
    `{ ok, batch: true, total, deleted, failed, skipped, results }`, где
    `results` — результат по каждой сессии (`ok`, `sessionId`, `code`,
    `message`, `warnings`). `skipped` — сессии с `code: live` (загружены в
    память DSH). Частичный отказ не отменяет уже удалённые сессии и приходит как
    `ok: false` + `failed > 0`; `live` не считается жёсткой ошибкой.
- **Глобальная команда** для ручного вызова и композиций без Connection:

  ```text
  /delete-archived session-<uuid>
  /delete-archived --check session-<uuid>   # только проверить, ничего не удаляя
  ```

Оба входа проверяют, что сессия архивная и не загружена в память DSH, затем удаляют:

- каталог журнала `~/.dsh/sessions/<проект>/<session-id>/` (у обычных сессий
  каталог назван полным id, у старых записей и субагентских — голым uuid;
  команда ищет оба варианта, а точный путь сначала берёт из
  `sessionPersistence.stat()`);
- кэш проекций: запись `session_projcache` через открытый storage-домен и
  legacy-файлы `~/.dsh/storages/session_projcache/sessions/<id>.json`;
- запись в реестре: убирает id из архива и из всех проектов, где он числится.

Если сессия открывалась в текущем запуске DSH, она может оставаться загруженной
в память даже после переключения на другую сессию. Хост не удаляет такую сессию
(файлы могут быть заняты, а живой агент — дописать журнал), поэтому нужен
перезапуск DSH; после него архивная сессия холодная и удаляется.

Индекс полнотекстового поиска (SQLite FTS) чистится сам при следующем поиске:
он сверяется с журналами и выкидывает исчезнувшие сессии.

## Откуда вызывается

- Из сайдбара `dsh-sidebar-opencode` 0.13.1+: у архивной строки есть корзина
  «Удалить навсегда» с подтверждением, а в настройках — «Удалить архивные (N)»,
  которая проходит по архиву теми же одиночными вызовами. Строки пропадают
  сразу, без открытия другой сессии и без служебной строки в чьём-либо журнале.
- Вручную из композера: `/delete-archived session-…`.

## Ограничения

- Только архивные сессии: живую сессию плагин не тронет.
- Если сессия ещё висит в памяти процесса, одиночное удаление попросит
  перезапустить DSH, а при массовом удалении такая сессия возвращается как
  `code: live`; остальные сессии всё равно обрабатываются.
- Пакетное удаление идёт последовательно и не атомарно: при частичном отказе
  успешные сессии остаются удалёнными, ошибочные возвращаются в `results`.
- Вложения сессии не удаляются: они общие для профиля и адресуются по хешу.
- Отменить удаление нельзя.

## Проверка

```powershell
node tools/test-session-purge.mjs       # временный DSH_HOME: удаление, кэш, реестр, HTTP-маршрут
node tools/smoke-sidebar-opencode.mjs   # корзина в сайдбаре вызывает удаление без открытой сессии
```

```text
plugin_manager install_bundle target=C:/projects/DeepseekPlugins/plugins/dsh-session-purge
```
