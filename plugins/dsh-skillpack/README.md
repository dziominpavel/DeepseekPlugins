# dsh-skillpack — рабочий набор навыков и команд

Один пакет, в котором лежит весь мой рабочий набор: навыки (`skills/`) и
команды-промпты (`commands/`). Поставил пакет — набор появился; перенёс
репозиторий на другую машину и выполнил `-Restore` — набор там тот же.

Навыки видны модели и вызываются из меню «/» (`/code-review`), команды — это
промпты, которые уходят в диалог от твоего имени (`/review src/app.ts`).

## Что внутри

```text
index.js              хост-половина: читает skills/ и commands/, регистрирует
cordis.patch.yml      строка skillpack в композиции профиля
skills/<имя>/SKILL.md навык: YAML-заголовок + инструкции; рядом можно держать
                      references/ и другие файлы — они доступны по относительному пути
commands/<имя>.md     команда-промпт: заголовок + текст, который уйдёт в диалог
locale/{ru,en}.json   название и описание для списка плагинов
icon.svg              иконка
```

В поставке семь навыков OpenSpec (основной рабочий процесс), навык
`simplify-code` (упрощение свежих правок четырьмя параллельными субагентами),
навык `code-review` с `references/severity.md` как пример формата и команда
`/review` как пример команды.

## Как добавить навык

1. Создай `skills/<имя>/SKILL.md` (имя — строчные латинские буквы, цифры,
   дефисы).
2. Заголовок:

   ```yaml
   ---
   name: release-notes
   description: Собирает список изменений для релиза из git log и группирует по смыслу.
   whenToUse: Просят «что в релизе», «release notes», «список изменений».
   ---
   ```

   `description` — одна строка, её видно в каталоге навыков, по ней модель
   решает, когда навык загружать. `whenToUse` необязателен.
3. Дальше — сами инструкции. Файлы рядом (`references/…`) навык может читать по
   относительному пути: в `code-review` так подключён `references/severity.md`.
4. Ничего перезапускать не нужно: правка подхватывается на следующем шаге.

Флаги в заголовке: `user-invocable: false` убирает навык из меню «/»,
`disable-model-invocation: true` запрещает модели загружать его самой.

## Как добавить команду

1. Создай `commands/<имя>.md`.
2. Заголовок и тело:

   ```markdown
   ---
   description: Готовит сообщение коммита по текущему дифу.
   hint: "[что-то уточнить]"
   ---
   Собери сообщение коммита: сначала строка-заголовок до 72 символов, затем
   тело по пунктам. Опирайся на git diff --staged.

   $ARGUMENTS
   ```

3. При вызове `/commit-msg` текст тела уходит в диалог как сообщение
   пользователя. `$ARGUMENTS` заменяется тем, что набрано после имени команды;
   без плейсхолдера ввод добавляется отдельным абзацем. Пустой `$ARGUMENTS`
   просто исчезает.

Команда ничего не делает сама: она отправляет промпт и запускает обычный ход
агента. Настоящие действия (маршруты, файлы, чистка) — это уже отдельные
хост-плагины, как `dsh-session-purge`.

## OpenSpec

Семь навыков — весь основной воркфлоу. В меню «/» они стоят рядом с
остальными, вызываются как `/openspec-propose`, `/openspec-apply-change` и так
далее; у OpenSpec для DSH нет отдельных слэш-команд, навык и есть команда.

| Навык | Что делает |
|---|---|
| `/openspec-explore` | Режим исследования: код, спеки, вопросы к владельцу до change |
| `/openspec-propose` | Новый change: proposal, design, дельты спек и tasks за один шаг |
| `/openspec-apply-change` | Выполнение задач change |
| `/openspec-update-change` | Правка плана change и согласование артефактов между собой |
| `/openspec-sync-specs` | Перенос дельт в основные спеки без архивации |
| `/openspec-archive-change` | Архивация завершённого change |
| `/openspec-pipeline` | Наш пайплайн: планировщик в диалоге + исполнитель-субагент |

Шесть навыков генерирует сам OpenSpec CLI (`openspec init --tools dsh`), их
руками не правят: при обновлении CLI перегенерировать и заменить. Седьмой,
`openspec-pipeline`, — наш собственный, генератор о нём не знает, правится
руками и при перегенерации не трогается.

Пересобрать навыки после обновления OpenSpec:

```powershell
$probe = "$env:TEMP\openspec-skills"
Remove-Item -Recurse -Force $probe -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Path $probe | Out-Null
Push-Location $probe; openspec init . --tools dsh --no-animation; Pop-Location
Copy-Item "$probe\.dsh\skills\openspec-*" "C:\projects\DeepseekPlugins\plugins\dsh-skillpack\skills\" -Recurse -Force
```

Строка `generatedBy` в заголовке файла показывает версию CLI, которой навык
собран; сравнить с `openspec --version` — самый быстрый способ понять, устарел
ли набор.

В проекте, где OpenSpec сгенерировал свои `.dsh/skills`, копии проекта главнее
набора: у них приоритет выше. Набор закрывает случай «открыл сессию вне такого
проекта» и новую машину.

Копий в `~/.dsh/skills` больше нет: единственный источник — набор. Если запустить
`openspec init` или `openspec update` в домашнем каталоге, файлы появятся там
снова; они будут затмеваться набором, то есть на работу не повлияют, но держать
их смысла нет.

## `/kit`

Служебная команда: печатает, какие навыки и команды загружены, с описаниями и
путём к каталогу набора. Быстрый способ проверить, что пакет подхватился.

## Установка и перенос

```text
plugin_manager install_bundle target=C:/projects/DeepseekPlugins/plugins/dsh-skillpack
```

На другой машине: склонировать репозиторий, `install.ps1 -Restore`, перезапустить
DSH. Пакет ставится как все остальные — каталог в `plugins/`, ссылка `link:` в
профиле, junction в `node_modules`. Встроенные плагины DSH при этом не
копируются: см. [docs/TRANSFER.md](../../docs/TRANSFER.md).

## Ограничения

- Набор виден сессиям, где включён плагин `tool-skill` (он есть в режимах PTC,
  «Стандартный» и «Создания»; в «Минимальном» навыков нет вовсе).
- Навык из рабочего проекта (`.dsh/skills`, `.agents/skills`) с тем же именем
  перекрывает навык набора: у проекта приоритет выше.
- Слежение за каталогом — через `fs.watch`: если ОС не даёт наблюдать папку,
  плагин пишет предупреждение и работает по состоянию на момент загрузки.
- Удалённый навык исчезает из каталога сразу, но если он уже был загружен в
  сессию, его текст остаётся в истории этой сессии.
