# dsh-sidebar-opencode

Список проектов и сессий в сайдбаре DSH, повторяющий привычки opencode:

- порядок сессий **только ручной**: новые падают в конец, перетаскивание мышью
  запоминается в `localStorage` (`dsh.opencode.order.v1`);
- у каждого проекта цветная буквенная иконка (цвет из хеша имени);
- список сессий внутри проекта сдвинут вправо на одну табуляцию (16px), как
  ветка дерева: спиннер, точка и «?» стоят не под иконкой проекта, а сразу за
  ней, поэтому строки читаются как вложенные;
- работающая сессия — крутящийся индикатор, завершённая и непросмотренная —
  зелёная точка;
- сессия, которая **встала и ждёт вас**, больше не выглядит работающей: у строки
  пульсирующий зелёный «?», зелёная подсветка и подсказка в `title`
  («Ждёт вашего ответа на вопрос» / «…подтверждения действия» /
  «…проверки плана»). У свёрнутого проекта рядом с названием видно зелёный
  счётчик «? N», заголовок окна мигает префиксом `● `. На появление ожидания
  играет отдельный сигнал (шесть нот), дальше — напоминание каждые 30 с, всего
  до 20 раз, пока не ответите. Всё это выключается в настройках списка;
- архивные сессии скрыты по умолчанию; включаются в настройках списка, отмечены
  меткой «архив», курсивом и приглушены; клик по такой строке возвращает её из архива;
- у архивной строки две кнопки: «вернуть из архива» и красная корзина
  «удалить навсегда» (с подтверждением). Удаление выполняет хост-команда
  `/delete-archived` из плагина `@local/dsh-session-purge`: стираются журнал,
  кэш проекций и запись в реестре. Удалённая строка пропадает сразу и не
  возвращается после перезагрузки;
- у каждой сессии на наведении есть кнопка «в архив» (для выполняющейся — с
  подтверждением остановки);
- у проекта есть стрелка-треугольник: клик по заголовку сворачивает и разворачивает
  список, состояние запоминается (`dsh.opencode.expanded.v1`); рядом с названием
  видно число сессий проекта (с учётом архивных) — свёрнутый проект больше не
  выглядит пустым;
- сессии, не привязанные ни к одному проекту (после удаления проекта или из старых
  данных), собраны в группу «Без проекта» в конце списка — раньше они были
  невидимы;
- в шапке списка — шестерёнка «Настройки списка»: галочки «Звук готовности»,
  «Звук, когда ждёт ответа», «Повторять напоминание», «Показывать архивные»,
  кнопки «Развернуть все»/«Свернуть все» и проверка обоих сигналов
  («Готовность» / «Ждёт ответа»);

Установка:

```text
plugin_manager install_bundle target=C:\projects\DeepseekPlugins\plugins\dsh-sidebar-opencode
```

Плагин заменяет слот `sidebar.workspaces`. Слот — `single`, и в DSH 0.2.2
штатный браузер регистрируется в нём на приоритете `0`, поэтому плагин
занимает `priority: -1000` (в `single`-слоте рендерится запись с наименьшим
приоритетом; `order` здесь не работает — он только для `list`-слотов).
Поиск, дерево workspace'ов, меню rename/archive/fork и hover-карточки
штатного браузера в этой версии не реализованы.

## Что попадает в список

- Ограничения по времени или количеству нет: показываются все сессии, которые
  клиент получил из каталога хоста, включая старые и архивные.
- Не показываются: пустые черновики (`blank`), субагентские сессии и строки,
  которых нет в каталоге клиента.
- У штатного сайдбара DSH свой водопад строк (5 на проект, «показать ещё» по 5,
  максимум 50) — здесь его нет, видны все.
- Архивные строки видны только при включённой галочке «Показывать архивные».
- Свёрнутый проект прячет все свои строки; число рядом с названием подсказывает,
  сколько их там. «Развернуть все» в настройках возвращает всё.
- Сессия, перетащенная в другой проект, показывается там со стрелкой «⇢».
- Удалить можно только архивную сессию и только когда она не загружена в память;
  после удаления строка прячется локально (`dsh.opencode.deleted.v1`), чтобы не
  ждать следующей перезагрузки списка.
- Каждое удаление выполняется командой в контексте открытой сессии, поэтому в её
  журнале остаётся служебная строка `/delete-archived`.

## Статус «ждёт ответа»

Источник — `uiSession.sessionStatus` (Map `sessionId → { running, pendingInteraction,
completionUnread }`). Пока агент ждёт ответа на `ask_user_question`, ход остаётся
`running: true`, поэтому раньше строка крутила спиннер, а сигнал готовности не
звучал: снаружи сессия выглядела работающей. Теперь `pendingInteraction.kind`
(`question`, `approval`, `plan-review`) главнее `running`: спиннер не рисуется,
вместо него — маркер ожидания, звук и напоминания.

Проверка без браузера:

```powershell
node tools/smoke-sidebar-opencode.mjs   # рендер списка на подставном React/DOM
```

## Ключи localStorage

`dsh.opencode.order.v1` (порядок), `dsh.opencode.expanded.v1` (свёрнутость
проектов), `dsh.opencode.sound.v1` (звук готовности), `dsh.opencode.alert.v1`
(звук ожидания ответа), `dsh.opencode.repeat.v1` (повтор напоминания),
`dsh.opencode.showArchived.v1`, `dsh.opencode.moved.v1`, `dsh.opencode.deleted.v1`.
