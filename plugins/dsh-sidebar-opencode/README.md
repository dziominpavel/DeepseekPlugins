# dsh-sidebar-opencode

Список проектов и сессий в сайдбаре DSH, повторяющий привычки opencode:

- порядок сессий **только ручной**: новые падают в конец, перетаскивание мышью
  запоминается в `localStorage` (`dsh.opencode.order.v1`);
- у каждого проекта цветная буквенная иконка (цвет из хеша имени);
- список сессий внутри проекта сдвинут вправо на одну табуляцию (16px), как
  ветка дерева: спиннер, точка и «?» стоят не под иконкой проекта, а сразу за
  ней, поэтому строки читаются как вложенные;
- работающая сессия — крутящийся индикатор, завершённая и непросмотренная —
  зелёная точка;
- сессия, которая **встала и ждёт вас**, больше не выглядит работающей: у строки
  пульсирующий зелёный «?», зелёная подсветка и подсказка в `title`
  («Ждёт вашего ответа на вопрос» / «…подтверждения действия» /
  «…проверки плана»). У свёрнутого проекта рядом с названием видно зелёный
  счётчик «? N», заголовок окна мигает префиксом `● `. На появление ожидания
  играет отдельный сигнал (шесть нот), дальше — напоминание каждые 30 с, всего
  до 20 раз, пока не ответите. Всё это выключается в настройках списка;
- архивные сессии скрыты по умолчанию; включаются в настройках списка, отмечены
  меткой «архив», курсивом и приглушены; клик по такой строке возвращает её из архива;
- проекты без сессий не показываются: когда последняя сессия проекта уходит в
  архив, проект исчезает из списка. При включённой галочке «Показывать архивные»
  проект с архивной сессией возвращается, а проект, в котором нет ни одной
  сессии, не показывается и тогда;
- пустой черновик (`blank`) не занимает строку, кроме текущего открытого: он
  рисуется строкой «Новая сессия». Поэтому проект, в котором вы начали новую
  сессию, сразу появляется в списке, даже до первого сообщения;
- у архивной строки две кнопки: «вернуть из архива» и красная корзина
  «удалить навсегда» (с подтверждением). Удаление выполняет хост-маршрут
  `POST api/session.purge` из плагина `@local/dsh-session-purge` (раньше это была
  команда `/delete-archived`): стираются журнал, кэш проекций и запись в
  реестре. Открытая сессия не нужна. Удалённая строка пропадает сразу и не
  возвращается после перезагрузки;
- у каждой сессии на наведении есть кнопка «в архив» (для выполняющейся — с
  подтверждением остановки);
- у проекта есть стрелка-треугольник: клик по заголовку сворачивает и разворачивает
  список, состояние запоминается (`dsh.opencode.expanded.v1`); рядом с названием
  видно число сессий проекта (с учётом архивных и текущего нового черновика) —
  свёрнутый проект больше не выглядит пустым;
- сессии, не привязанные ни к одному проекту (после удаления проекта или из старых
  данных), собраны в группу «Без проекта» в конце списка — раньше они были
  невидимы;
- в шапке — шестерёнка «Настройки списка». Панель разбита по смыслу:
  «Список» — «Развернуть все»/«Свернуть все»;
  «Архив» — «Показывать архивные» и «Удалить архивные (N)» с подтверждением;
  «Уведомления» — «Звук готовности» и «Звук, когда ждёт ответа» с маленькой
  кнопкой-динамиком для проверки прямо в строке, «Повторять напоминание»
  (недоступно без звука ожидания) и подсказка про интервал. Панель закрывается
  только повторным нажатием шестерёнки: клик по сессии или другому месту
  списка её не сбрасывает;

Установка:

```text
plugin_manager install_bundle target=C:\projects\DeepseekPlugins\plugins\dsh-sidebar-opencode
```

Плагин заменяет слот `sidebar.workspaces`. Слот — `single`, и в DSH 0.2.2
штатный браузер регистрируется в нём на приоритете `0`, поэтому плагин
занимает `priority: -1000` (в `single`-слоте рендерится запись с наименьшим
приоритетом; `order` здесь не работает — он только для `list`-слотов).
Поиск, дерево workspace'ов, меню rename/archive/fork и hover-карточки
штатного браузера в этой версии не реализованы.

## Что попадает в список

- Ограничения по времени или количеству нет: показываются все сессии, которые
  клиент получил из каталога хоста, включая старые и архивные.
- Не показываются: пустые черновики (`blank`), кроме текущего открытого (он
  рисуется строкой «Новая сессия»), субагентские сессии и строки, которых нет в
  каталоге клиента.
- Проект без видимых сессий не рисуется. Поэтому после архивации последней
  сессии проект пропадает; при включённой галочке «Показывать архивные» он
  возвращается, если в нём есть архивная сессия. Проект без единой сессии не
  показывается никогда.
- Если в списке не осталось ни одного проекта, выводится «Нет проектов с
  сессиями», а при скрытом архиве — подсказка включить «Показывать архивные».
- Кнопки добавления проекта в шапке нет: проект добавляется через экран новой
  сессии / выбор workspace. Если проект добавлен без сессии, он не появится —
  это то же правило, что и для пустых проектов.
- У штатного сайдбара DSH свой водопад строк (5 на проект, «показать ещё» по 5,
  максимум 50) — здесь его нет, видны все.
- Архивные строки видны только при включённой галочке «Показывать архивные».
- Свёрнутый проект прячет все свои строки; число рядом с названием подсказывает,
  сколько их там (архивные и текущий новый черновик тоже считаются).
  «Развернуть все» в настройках возвращает всё.
- Сессия, перетащенная в другой проект, показывается там со стрелкой «⇢».
- Удалить можно только архивную сессию и только когда она не загружена в память
  DSH. Если сессия открывалась в текущем запуске, она может остаться в памяти
  даже после переключения на другую — тогда нужен перезапуск DSH; после удаления
  строка прячется локально (`dsh.opencode.deleted.v1`), чтобы не ждать следующей
  перезагрузки списка.
- Удаление идёт отдельным `POST api/session.purge`, поэтому не требует открытой
  сессии и не оставляет служебную строку в журнале.

## Статус «ждёт ответа»

Источник — `uiSession.sessionStatus` (Map `sessionId → { running, pendingInteraction,
completionUnread }`). Пока агент ждёт ответа на `ask_user_question`, ход остаётся
`running: true`, поэтому раньше строка крутила спиннер, а сигнал готовности не
звучал: снаружи сессия выглядела работающей. Теперь `pendingInteraction.kind`
(`question`, `approval`, `plan-review`) главнее `running`: спиннер не рисуется,
вместо него — маркер ожидания, звук и напоминания.

## Настройки списка

Панель открывается шестерёнкой в шапке и остаётся открытой, пока её не закроют
повторным нажатием: клик по сессии, проекту или пустому месту списка её не
сбрасывает. Это сделано намеренно — настройки не мешают параллельно работать
со списком.

Группы:

- **Список** — кнопки «Развернуть все»/«Свернуть все».
- **Архив** — «Показывать архивные» и красная кнопка «Удалить архивные (N)».
  Она проходит по архиву и вызывает то же одиночное удаление, что и корзина у
  строки, — по одному вызову на сессию; после подтверждения под кнопкой видно,
  сколько удалено, а при частичном отказе — сколько не удалось.
  Пока идёт удаление, кнопка показывает прогресс и недоступна. Счётчик считает
  только реальные сессии из каталога: служебные записи архива без файлов и без
  строки в списке не показываются и в N не входят. В обработку входят все
  реальные архивные сессии, включая ту, что сейчас открыта: хост пропускает
  только действительно загруженные в память DSH. Результат такого пропуска
  показывается как «в памяти DSH N», без модального окна с ошибкой; удалить
  такую сессию можно после перезапуска DSH.
- **Уведомления** — звук готовности и звук ожидания ответа. Проверка сигнала
  стоит рядом с соответствующим переключателем в виде кнопки с динамиком:
  не нужно искать отдельные кнопки «Готовность»/«Ждёт ответа» внизу панели.
  «Повторять напоминание» вложено под звук ожидания и недоступно, пока этот
  звук выключен. Техническая строка про AudioContext из панели убрана.

Принципы, по которым перестроена панель, и что было до этого —
[docs/UI-SETTINGS-AUDIT.md](../../docs/UI-SETTINGS-AUDIT.md).

Проверка без браузера:

```powershell
node tools/smoke-sidebar-opencode.mjs   # рендер списка на подставном React/DOM
```

## Ключи localStorage

`dsh.opencode.order.v1` (порядок), `dsh.opencode.expanded.v1` (свёрнутость
проектов), `dsh.opencode.sound.v1` (звук готовности), `dsh.opencode.alert.v1`
(звук ожидания ответа), `dsh.opencode.repeat.v1` (повтор напоминания),
`dsh.opencode.showArchived.v1`, `dsh.opencode.moved.v1`, `dsh.opencode.deleted.v1`.
