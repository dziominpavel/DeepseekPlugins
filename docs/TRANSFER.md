# Перенос плагинов и настроек профиля

Короткий ответ: **настройки профиля хранятся в репозитории, а не копии
встроенных плагинов**. Копировать код DSH в проект не нужно и опасно; достаточно
зафиксировать, какие bundles включены и какой у профиля cordis.patch.yml.

## Слои

    DSH (resources/app.asar)     код встроенных плагинов, обновляется вместе с DSH
    ~/.dsh/profiles/<profile>    выбор плагинов (package.json) и настройки (cordis.patch.yml)
    DeepseekPlugins/plugins/     код моих плагинов
    DeepseekPlugins/profile/     переносимый снимок профиля

Встроенные плагины уже есть в DSH. Чтобы они «перенеслись», не нужен их код —
нужно, чтобы в новом профиле были те же имена в dsh.profile.bundles. Именно это
и делает снимок.

Настройки встроенных плагинов — «Субагент», «Веб-поиск», «Цикл агента»,
«Ракушка» — сервис settings сохраняет через Cordis patch профиля, то есть в
cordis.patch.yml. Отдельный экспорт для них не нужен: они уже в снимке.

## Почему не копии встроенных плагинов

- **Версия.** Встроенный плагин связан с версией DSH и его внутренними
  контрактами. Копия в репозитории заморозится и после обновления DSH может
  просто не загрузиться.
- **Зависимости.** У встроенных пакетов свои peer-зависимости и ассеты внутри
  app.asar; вытащить их полностью — это уже форк DSH.
- **Обновления.** Обновление DSH перезаписывает resources; копии пришлось бы
  синхронизировать вручную.
- **Лицензии и размер.** Копирование кода приложения в свой репозиторий — лишний
  юридический и технический груз.

Снимок хранит только **имена** встроенных bundles и **конфигурацию** профиля.
Код остаётся у DSH.

## Что делает install.ps1

### -Capture

Читает текущий профиль и пишет:

    profile/<profile>/profile.json
    profile/<profile>/cordis.patch.yml

В profile.json:

- schema — версия формата снимка;
- profile — имя профиля;
- dshVersion — версия DSH, с которой снят снимок;
- plugins — все локальные плагины из plugins/ на момент снимка;
- bundles — упорядоченный список включённых bundles;
- remoteDependencies — необязательные зависимости из реестра.

Перед записью cordis.patch.yml проверяется на секреты. Если в поле apiKey,
token, secret или password стоит значение, не похожее на имя переменной
окружения, снимок не сохраняется.

### -Restore

1. Делает резервную копию профиля в docs/recovery/restore-<дата>-<профиль>.
2. Прописывает link-зависимости для всех плагинов из plugins/.
3. Проверяет, какие bundles из снимка существуют в текущей установке DSH;
   отсутствующие пропускает с предупреждением.
4. Собирает список bundles: локальные — строго по снимку; встроенные — по
   снимку плюс текущие (если не указан -Exact).
5. Копирует cordis.patch.yml из снимка.
6. Создаёт junction и правит записи в pnpm-lock.yaml.

После этого нужен перезапуск DSH: состав клиентских модулей собирается заново.

### -Exact

Без ключа -Restore сохраняет встроенные bundles, которых нет в снимке. Это
защищает от ситуации «в новой версии DSH появился обязательный bundle, а старый
снимок его не знает». Ключ -Exact заменяет список ровно снимком — полезно,
когда нужно клонировать состав один в один.

## Сценарии

### Новый компьютер

    # на старом компьютере
    C:/projects/DeepseekPlugins/install.ps1 -Capture
    git add profile
    git commit -m "profile snapshot"
    git push

    # на новом
    # 1. установить DSH и один раз запустить
    # 2. закрыть DSH
    git clone <repo> C:/projects/DeepseekPlugins
    C:/projects/DeepseekPlugins/install.ps1 -Restore
    # 3. запустить DSH, проверить Настройки -> Плагины

### Новая версия DSH на той же машине

    # 1. обновить DSH, запустить один раз, закрыть
    C:/projects/DeepseekPlugins/install.ps1 -Restore
    # 2. проверить предупреждения о пропущенных bundles
    # 3. поправить состав в Плагинах и сделать -Capture

### Добавили новый плагин

    # 1. добавить каталог в plugins/
    # 2. поставить/включить его в DSH
    C:/projects/DeepseekPlugins/install.ps1 -Capture

### Плагин выключен намеренно

Он остаётся в profile.json в списке plugins, но его нет в bundles. -Restore
поставит link-зависимость, но не включит bundle. -Fix тоже не включит его
обратно: снимок знает, что плагин был и был выключен.

## Проверка

    C:/projects/DeepseekPlugins/install.ps1
    C:/projects/DeepseekPlugins/install.ps1 -Fix

Первая команда только проверяет, вторая чинит link, junction и lock. В конце
печатается расхождение с снимком, если оно есть.

## Ограничения

- Снимок не переносит ~/.dsh/.credentials.yaml, сессии, workspace и
  localStorage браузера.
- Внешние плагины из реестра прописываются в зависимости, но их установка
  (pnpm install) не выполняется автоматически: после -Restore поставьте их
  через страницу **Плагины** или pnpm.
- cordis.patch.yml копируется целиком. Если на целевой машине уже есть свои
  настройки, -Restore перезапишет их; перед записью лежит бэкап в
  docs/recovery.
- Настройки сайдбара (порядок сессий, звук, свёрнутость проектов) живут в
  localStorage и в снимок не входят.
